# Security
Implemented: env-based config; `.env` git-ignored; `.env.example` has disposable dev credentials only; failure injection gated by `ENABLE_DEV_ENDPOINTS` **and** `SAGAFLOW_ENV in {development,test}` (endpoint returns 404 otherwise, `simulate` in orders is ignored); admin actions (retry/recover) need `X-Admin-Token` (constant-time compare) or dev mode; pydantic validation; 64 KB request limit; no stack traces in responses; no payment data stored or logged (no card fields exist); containers run as non-root; all published ports bind to 127.0.0.1; health checks.

**Not production-ready.** Before any public deployment you would need: real authentication/authorization for all endpoints (users, roles) instead of one shared admin token; TLS everywhere; secrets manager and per-service least-privilege DB roles (all services currently share one Postgres user); a non-default RabbitMQ user per service with vhost permissions; rate limiting; audit logging of admin actions; dependency/image scanning and pinned image digests; backups; network policies; a real payment provider integration with PCI scope review.
